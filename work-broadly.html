Broad.ly

A WhatsApp broadcast platform: templated messaging, delivery tracking, and CSV-based sends, built to run for any business rather than one.

Role
UI/UX Design

The brief

Sending WhatsApp messages at scale means working directly against Meta's Business API: template approvals, variable payloads, per-message cost, delivery status. Broad.ly wraps that in a dashboard any business can use without touching the API by hand: build a template once, map a spreadsheet of recipients to it, and send. Kristu Jayanti's admissions office came on as the first sender, using it to push application and enrolment updates over WhatsApp; the templates in these screens are theirs, but the tool underneath isn't built for one office alone.

The pitch before the product

Broad.ly needed a front door as much as a back office: a landing page that explains what it does (message scheduling, easy send, history and monitoring) before a sender ever logs in, with sign-in sitting right on top rather than tucked behind a separate route.

What you'll send, before you send it

Sending a templated WhatsApp message means filling in variables blind unless you can see the result. The compose screen keeps a live phone preview next to the form, so mapping {{body_var_1}} to an actual name or application number shows exactly what the recipient is about to receive, before Review & Send is even a click away.

Every send is accountable

Each row in History is one message, one recipient, one outcome: delivered, pending, or failed, with the per-message cost and timestamp next to it. Nothing about a WhatsApp broadcast tool matters more than being able to answer "did this actually go through," so that answer is the whole screen.

Reusable, not rebuilt each time

A sender rarely writes a new message from scratch. They reuse an admission reminder, an OTP notice, a welcome message, with different names dropped in. Templates lists what's already approved and ready, with its variables visible at a glance, so Send Message starts from a dropdown instead of a blank field.

Where the dashboard meets the API

Under a template name and a list of variables sits the thing this whole product exists to hide on every other screen: the raw WhatsApp Business API payload. Creating a template is the one place that complexity has to surface. Everywhere else, it's the variable mapping a sender fills in, not the JSON underneath it.
